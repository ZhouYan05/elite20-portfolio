# 交接说明 — kstar-aar-generator 技能包

> 接收方：宋君毅｜封装方：周岩（2024102310451）｜版本：2026-11-16

## 1. 这个技能解决什么问题

写 AAR 时最容易出的三种毛病：漏掉 ΔR（预期与实际的偏差）、下周计划写成流水账、失败分析变成情绪宣泄。这个技能把结构固定下来，你只需要提供事实，结构由流程保证。

## 2. 前置条件（缺一不可）

- 手边有一个**真实发生过的任务**（这周做过的挑战、项目、实验都行）；
- 能说出三样东西：预期产出 R̂、实际产出 R、卡在哪（1–3 句即可）；
- 知道"不许事后修改 R̂"这条铁律——ΔR 的价值就在不一致里。

## 3. 最小操作流程

1. 取 `skill/kstar-aar-generator/SKILL.md`，按其步骤走；
2. 素材三件（R̂ / R / 卡点）先写下来，不要边写边美化；
3. 生成六段结构：S 情境 / T 任务 / A 行动 / R 结果 / ΔR 偏差 / 失败分析 / 下周计划；
4. **人工审校是必经步骤**：逐句核对是否为真实发生的事，工具只搭结构；
5. 导出 Markdown，按课程提交格式落盘。

在线版（可选）：`https://ZhouYan05.github.io/elite20-aar-writer/`

## 4. 三类常见失败与自救路径

| 现象 | 大概率原因 | 自救 |
| --- | --- | --- |
| 生成结果缺 ΔR 段 | 你把 R̂ 和 R 写成了一回事 | 先强行写出"本以为…结果…"的差异，再回填 |
| 下周计划像清单堆砌 | 没有对齐失败分析 | 让每条计划对应一条失败点或一条偏差 |
| 失败分析写成情绪 | 没区分事实与评价 | 只保留"现象 + 我试了什么 + 卡在哪"三段 |

## 5. 边界（不要误用）

- 不适用于需要量化统计的实验报告——AAR 是复盘，不是数据分析；
- 不替你判断"这件事该不该做"，它只处理已发生的事；
- 不允许用它生成未发生的内容：一旦无中生有，整份复盘作废。
