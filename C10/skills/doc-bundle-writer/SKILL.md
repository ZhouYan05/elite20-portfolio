# 交付文档包生成器

输入：挑战 ID + 该挑战实际执行过程素材（做了什么、AI 怎么用的、借鉴了什么）。
输出：README.md + 姓名_挑战_AI日志.md + 姓名_挑战_拿来说明.md +（需要的）AAR/链接类文档，文件名与挑战 deliverables_pattern 逐一匹配。

## 步骤

1. 读取挑战规范，提取「提交内容」表与文件名模式；
2. 用脚本核对交付目录文件名是否覆盖 deliverables_pattern 全部子串；
3. AI 日志三段式：阶段（Prompt 要点 / AI 产出 / 人工决策）+ 踩坑 + 手动步骤反向举证；
4. 拿来说明表格式：来源 / 拿了什么 / 改了什么 + 刻意不采用的部分 + 引用合规；
5. README 总览：级别/要求核对表 + 交付物清单 + 关键链接。

## 迭代记录（CHANGELOG）

- v1（2026-11-10）：各文档分别手写 → 格式不统一（AI 日志有的缺反向举证，拿来说明有的缺合规段）。
- v2（2026-11-10）：固化为本三段式/表格式模板，并增加「文件名模式脚本核对」步骤，杜绝平台因缺交付物退回。

## 约束

- AI 日志必须真实：记录的是实际发生的 Prompt 与迭代，禁止事后编造；
- 拿来说明必须具体到「哪一节、哪个字段」，禁止笼统写「参考了网络」。
