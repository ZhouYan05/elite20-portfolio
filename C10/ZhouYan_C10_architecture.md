# ZhouYan_C10_architecture：五层架构 + 设计决策

> 任务：C10 Build Your Own Agent（构建你的长期智能体 第二大脑）
> 完成人：周岩（2024102310451）｜日期：2026-11-10

## 一、五层架构总览

```
L1  Agent Core（智能体核心）   AGENT.md：身份、循环、调用规则
        │ 每次执行产生 AAR
L2  Experience（经验层）       L2_experiences/：KSTAR AAR 原文
        │ 反复出现 3 次以上的经验被提炼
L3  Skill（技能层）            ZhouYan_C10_skills/：6 个可复用技能
        │ 技能调用「工具层」的能力
L4  Tools（工具层）            L4_tools/：可复跑脚本与流程（gh、headless Edge、
        │                        gen_report.py、CogSeed 提交命令）
L5  Knowledge（知识层）        L5_knowledge/：课程规范、挑战目录、术语表
```

**循环方向**：L1 执行 → 经验落入 L2 → 提炼进 L3 → 技能借用 L4 → 规范沉淀于 L5；下次执行时 L3/L5 反向加载回 L1。这就是「第二大脑」：对话会结束，但经验、技能与规范留在目录里。

## 二、设计决策（每条都对应一次真实教训）

### 决策 1：一切从 AAR 开始——KSTAR 是唯一复盘格式

**决策**：L2 经验层只存 KSTAR 结构（S/T/A/R/ΔR/失败分析/下周计划），不用自由日记。
**理由**：课程 C8/C9 要求周度 AAR；自由格式的经验无法对比、无法检索「偏差」。统一结构后，「R̂ vs R」成为可聚合的数据，而不是散文。
**代价**：写 AAR 的启动成本略高 → 用 `kstar-aar-generator` 技能对冲（表单输入，30 秒产出骨架）。

### 决策 2：技能 = 目录 + frontmatter + 使用记录

**决策**：每个技能是一个目录：`SKILL.md`（触发条件/输入/输出/步骤）+ `USAGE.md`（使用记录）+ 必要的脚本。
**理由**：直接来自 C5A 分析 neoskills 的收获——「技能是数据，不是散落的提示词」。frontmatter 的 description 是给 agent 的检索摘要，「Use when…」触发场景写法来自社区验证过的最佳实践。
**代价**：目录维护有纪律成本 → 用 AGENT.md 的「技能调用规则」强制执行使用记录。

### 决策 3：工具层只放「可复跑」的流程

**决策**：L4 工具的标准是「输入参数 → 输出产物」的确定性流程（如 `gen_report.py <data_dir>`、headless Edge 验证命令），个人化、一次性的操作不进入工具层。
**理由**：C6A 数据管线的教训——把「生成仪表盘」做成一条可复跑命令后，数据更新从 30 分钟手工变成 1 条命令；不可复跑的流程每次都要重新摸索。
**代价**：脚本化有前期成本 → 只有「本周用了 2 次以上」的流程才脚本化。

### 决策 4：单一事实源（Single Source of Truth）

**决策**：同类信息只存一份，其余全部生成。例：提交记录只存 `submissions.json`，CSV/Excel/data.js/周报全部由生成器产出；技能内容只存技能目录，agent 目标处用引用。
**理由**：C10 之前我吃过「多副本漂移」的亏——同一个技能被复制到多个 agent 目录后各自演化（这条教训直接写进了 C5A 分析报告的学习收获 2）。
**代价**：需要生成器维护成本 → 生成器本身是可复跑工具（决策 3），成本摊薄。

### 决策 5：密钥与账号操作只走环境变量，不落盘

**决策**：任何 API Key 不写进文件；账号登录态只存在于各 CLI 自身（gh auth）；提交平台的 Key 只从运行环境注入。
**理由**：C6 规范的「Key 安全提醒」+ 公开仓库的现实约束（README 里写得很清楚：Key 只存 localStorage，只发往用户自填的 Base URL）。
**代价**：自动化受限于「环境是否已注入密钥」→ 把这部分流程标注为「半自动」，人工步骤记录在案。

## 三、架构与课程的映射

| 课程挑战 | 在本架构中的落点 |
|---|---|
| C1–C2（翻译/论文） | L2 经验 + L3 `doc-bundle-writer`、L5 术语表 |
| C3（讨论） | L2 反思 + L3 `kstar-aar-generator` |
| C4（技能） | 直接进入 L3 技能库（AAR 生成技能的原型） |
| C5/C5A（GitHub） | L4 工具层：`github-publisher`、git 工作流 |
| C6/C6A（Web/仪表盘） | L4 工具层：`headless-verifier`、`data-dashboard` |
| C7（内容传播） | L3 `doc-bundle-writer` + `kstar-aar-generator` |
| C8/C9（项目执行/自驱） | L2 大量 KSTAR 经验 + L3 项目技能 |
| 提交（平台） | L4 工具层：`cogseed-submitter` |

## 四、演进计划

- v1.1（两周内）：技能间依赖关系引入本体层描述（借鉴 neoskills ontology，见 C5A 分析）；
- v1.2（一个月内）：L2 经验「ΔR 聚合周报」自动化——每周自动统计各技能偏差率，输出技能迭代候选清单；
- v1.3：把本架构打包成可分享的「Elite20 学习智能体模板」，供同学 clone 即用。
