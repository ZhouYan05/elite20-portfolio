# ZhouYan_C10_AI日志：构建过程的 AI 使用记录

> 任务：C10 Build Your Own Agent｜时间：2026-11-10｜方式：Claude Code 辅助，人负责决策与真实性核对

## 阶段 1：架构设计（约 20 分钟）

- Prompt 要点：「为 Elite20 C10 设计五层智能体架构，参考挑战规范的五层图；结合我这两周的真实工作流，指出哪些流程值得技能化」。
- AI 产出：五层架构骨架 + 技能候选清单。我逐条对照真实经历筛选：候选里的「竞品调研」「周计划」技能我没有真实使用记录 → 删除；保留并补充「cogseed-submitter」「headless-verifier」这两个我有大量真实记录的工作流。
- 人工决策：技能宁缺毋滥——「真实使用过」是不可协商的底线（挑战规范明确写了反例）。

## 阶段 2：技能提炼（约 40 分钟）

- Prompt 要点：「按 SKILL.md 规范写 6 个技能：frontmatter + 触发场景 + 步骤 + 约束 + CHANGELOG；每个配 USAGE.md」。
- 关键交互：
  1. AI 初稿把「使用记录」写得像功能宣传 → 我要求每条记录必须能对应真实日期与事件（如 2026-10-04 C4C 84 分、2026-11-10 各次发布），无法对应的删除；
  2. headless-verifier 的踩坑参数（--virtual-time-budget、独立 profile）由我提供当天实测经历，AI 整理成「关键参数」段；
  3. 每个技能的迭代记录都必须有「改进动机」——来自真实返工事件，而不是为了好看编的版本号。

## 阶段 3：文档交付（约 30 分钟）

- Prompt 要点：「写 architecture（五层 + 设计决策）、系统级 AAR（KSTAR）、usage_log（含 3 个规范格式的详细场景）、拿来说明」。
- 我的修改：
  1. 设计决策每条补「代价」——只写理由不写代价的决策记录是自我美化；
  2. AAR 的 ΔR 段保留三条真实偏差（技能数 5→6、demo 形式、cogseed-submitter 记录回溯），不粉饰；
  3. usage_log 的三个详细场景全部从技能 USAGE.md 汇总，不新增口径不一致的内容。

## 手动步骤反向举证

- 技能清单筛选、使用记录真实性核对、设计决策与教训的对应关系均为人工作出；
- 所有使用记录中的人名、日期、分数（84 分）、URL 均由我提供或来自平台/GitHub 实际记录，AI 未虚构。
