## 失败分析

- 失败点：初版原型对「大纲缺字段」会 KeyError 中断 → 归因：我按「输入总是规范」的假设写代码；对策：缺字段回退占位文案并继续（已验证）。教训：流水线的鲁棒性要求「脏输入不断线」。
- 失败点：AI 润色功能最初想内置一个固定 Key → 归因：违反我自己的「Key 不落盘」原则；对策：环境变量注入 + 无 Key 自动回退模板，且回退路径成为默认演示路径。

## 本周发现（比之前的方案更好）

本周我评估了「用现成 LMS/课程平台做交付段」与「用静态生成 + GitHub Pages 做交付段」两个方案：现成 LMS 功能全但学员侧有注册门槛、我无法定制归档接口；静态生成零门槛、与「单一事实源 + 生成器」模式天然同构。结论：现有方案（静态生成）仍是最优，因为本项目的验收标准是「学员零安装 + 归档可自动」，而非「功能最多」。
