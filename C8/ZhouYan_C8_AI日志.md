# ZhouYan_C8_AI日志：Proposal 写作与原型开发的 AI 使用记录

> 任务：C8 Real-World Project（Project C 课程生产体系）｜时间：2026-11-10

## 阶段 1：项目选择（约 20 分钟）

- Prompt 要点：「把 C8 的 A/B/C 三个项目与我的 C1–C7 产出做匹配分析，指出每个项目我能拿出的具体证据」。
- AI 产出：三项目×我的证据对照表。我选择 C：证据链最强（C1 翻译→内容生产、C4C→内容自动化、C6A→生成管线、C5/C6→工具固化），且与 C10 智能体的技能库形成正循环。
- 人工决策：否决 Project B（企业本体 Agent）——我的知识图谱经验不足且无企业数据源，硬选会写不出「拿来说明」的真实调研。

## 阶段 2：拿来主义分析（约 30 分钟）

- Prompt 要点：「为 Project C 列参考来源并做 adopted/removed/improved 分析，重点区分『复用』『改造』『新增』」。
- AI 产出：初稿列了 6 个来源。我删掉 2 个与我实际没读过的来源（保持「拿来说明」的真实性底线），并把「去掉多智能体适配层」「去掉企业级本体建模」的理由改写为我在 C5A 分析中形成的第一手判断。

## 阶段 3：原型开发（约 1.5 小时）

- Prompt 要点：「写一个零依赖 Python 脚本：解析大纲 Markdown（## 第N周 + 主题/目标/素材），生成内容框架；可选 AI 润色，失败回退」。
- 关键迭代：
  1. AI 初版用第三方 markdown 库 → 我要求零依赖（与流水线「可复跑」目标一致，且避免依赖漂移）；
  2. 缺字段中断问题由我实测发现 → 加占位回退；
  3. AI 润色段由我坚持「环境变量注入 + 无 Key 回退」，与 C6 的 Key 安全原则一致。
- 实测：3 周示例大纲跑通，产物结构完整。

## 阶段 4：AAR 与文档（约 40 分钟）

- 用 kstar-aar-generator 技能生成 AAR 骨架，我填写真实耗时与偏差（快于预期 40%、契约代码化等均为真实情况）；
- doc-bundle-writer 生成文档包，文件名与 deliverables_pattern 核对通过。

## 手动步骤反向举证

- 项目选择、来源删减、零依赖要求、Key 安全约束均为人工作出；
- AAR 中的耗时数字来自当日实际执行（可对照本会话记录），AI 未虚构。
